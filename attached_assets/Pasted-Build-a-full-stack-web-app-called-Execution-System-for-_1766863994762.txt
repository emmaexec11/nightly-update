Build a full-stack web app called Execution System for goal and habit tracking. The system is designed to show whether a user is statistically ON TRACK toward long-term goals using only daily habit execution, not emotional checklists.

This app must prioritize speed (under 60 seconds per day), clarity, and correct math.

CORE PHILOSOPHY (NON-NEGOTIABLE)

Only daily habits are checked off.

Goals (Year / Quarter / Month / Week) are read-only context, never checked off.

Progress is judged by cumulative success percentage, not streak obsession or perfection.

“Not required” days must be automatically excluded from all calculations.

The system must survive missed days and never punish emotionally — only mathematically.

GOAL STRUCTURE (LAG INDICATORS)

Goals exist only for context and hierarchy:

Yearly

Quarterly

Monthly

Weekly

Each goal has:

name

type (Yearly | Quarterly | Monthly | Weekly)

parent_goal_id (to form hierarchy)

start_date (optional)

end_date (optional)

description

target_success (default 0.80)

notes

“Current” goals are determined by date ranges if present; otherwise, the most recent goal of each type.

HABITS (LEAD INDICATORS)

Habits drive all scoring.

Each habit has:

name

linked_goal_id (usually Weekly or Monthly)

required_days (array of day names: Mon Tue Wed Thu Fri Sat Sun)

frequency_type (Daily / Weekly — stored for future use)

notes

Important:
Do NOT store “required” per day.
Required status is always computed from:

habit.required_days

day-of-week of the date being viewed

DAILY CHECK-INS (AUTO-RESET BEHAVIOR)

Each calendar day has its own check-in.

Checkboxes reset automatically because completion is stored per date.

When the app opens, it always defaults to Today.

When the date changes, the UI automatically shows a fresh day.

No manual reset buttons. Ever.

DATA MODEL (REQUIRED)

Use a database (SQLite is fine) with these tables:

Goals

(id, name, type, parent_goal_id, start_date, end_date, description, target_success, notes)

Habits

(id, name, linked_goal_id, required_days, frequency_type, notes)

DailyCheckins

(id, date UNIQUE, notes)

HabitChecks

(id, date, habit_id, completed BOOLEAN, UNIQUE(date, habit_id))

WeeklyReviews (optional metrics)

(id, week_start, week_end, weight, training_sessions, nervous_system_score, notes)

SCORING LOGIC (CRITICAL — MUST BE CORRECT)
Required Instances

For any time range:

Required instances = count of dates where:

the habit exists

AND the habit is required on that weekday

Completed Instances

Completed instances = required instances where completed = true

Success %
success % = completed_instances / required_instances

Status

ON TRACK if success % ≥ 0.80

OFF TRACK if < 0.80

Cumulative Success

Cumulative success is calculated across all historical data

It never resets (not weekly, not monthly)

On one screen, show:

Current Yearly Goal

Current Quarterly Goal

BOTTOM (Action)

Only TODAY’S REQUIRED HABITS

Show:

Daily success %

Cumulative success %

Large ON TRACK / OFF TRACK indicator

STREAKS (PER HABIT)

For each habit, compute:

Current Streak

Number of consecutive required days completed up to today

Non-required days:

Do NOT count

Do NOT break streaks

A streak breaks only when a required day is missed.

Display:

Streak: X days

“DON’T MISS TWO IN A ROW” WARNING

For each habit required today:

Show a warning if:

The habit was required on the previous required day

AND it was not completed on that day

Important:

“Previous required day” ≠ yesterday if yesterday wasn’t required

Example: If habit is Mon–Sat, missing Saturday should warn on Monday

Display a clear visual warning:

“⚠️ Missed last required day — don’t miss two in a row”

HABIT DETAIL VIEW (CLICK TO OPEN)

Clicking a habit opens a detail screen with:

1) Monthly Calendar View

Show current month grid

Each day marked as:

✅ Completed (required + done)

❌ Missed (required + not done)

⬜ Not required (grey / blank)

Calendar is computed from:

habit.required_days

habit_checks by date

2) Time-Range Performance

For this habit, show success % for:

This week

This month

This year

All time

Each range must exclude not-required days automatically.

FINAL CONSTRAINTS (VERY IMPORTANT)

Never count “not required” days as required

Streaks must ignore non-required days

“Missed last day” warnings must reference the last required day, not simply yesterday

All success percentages must be mathematically correct and consistent across views
